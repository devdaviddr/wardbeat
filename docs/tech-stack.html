Stack & why

Every technology in WardBeat, what it does, and — the part that matters — why it was chosen over the obvious alternative. The through-line is right tool per tier and data sovereignty for clinical data.

How it works In the hospital Stack & why One-pager

The two decisions behind everything

Polyglot by design. TypeScript runs the product tier; Python runs the AI tier — because the GenAI/ML ecosystem (retrieval, agents, evals, scikit-style models) lives in Python. Not language sprawl: one internal service, behind one front door.
On-prem-capable by default. The whole AI stack (NVIDIA NIM) is self-hostable, so patient-adjacent data can stay inside the hospital. For clinical data that's not a preference — it's often the deciding requirement, and it rules out hosted frontier APIs.

Product tier

Next.js 16

Experience · BFF

App Router, React Server Components, and Server Actions — the UI, the auth boundary, and the API-for-the-frontend in one framework.

  • Server Actions let the browser talk to one front door; the AI service and DB stay server-side and unexposed.
  • RSC keeps the board fast — data assembled on the server, no client data-fetching spaghetti.
  • It's the platform the project was scaffolded on, so auth, RBAC, PWA and the app shell came for free — leaving the build to be about the AI.

Instead of a separate SPA + standalone API: more surface, duplicated auth, and a second thing to deploy — for no gain here.

Drizzle ORM + PostgreSQL 17

Data

Type-safe schema and queries in TypeScript over Postgres; migrations generated from the schema.

  • End-to-end types from column to component — the read models are compile-checked.
  • Single migration authority. One place owns the schema, which keeps the polyglot setup honest (Python reads, never migrates).
  • Postgres is boring in the best way: transactional, ubiquitous, and — with pgvector — does double duty (below).

Instead of a heavyweight ORM or hand-rolled SQL: Drizzle keeps the types without the magic.

AI tier

FastAPI (Python 3.12)

AI plane · internal

A small, stateless internal service: extraction, RAG answer, the recommender agent, forecasting, and narration.

  • Python is where the AI ecosystem lives — retrieval, agent orchestration, evaluation, and scikit-style models. Building that in TypeScript would fight the grain.
  • Stateless pure functions of their inputs → trivially testable, and the DB keeps a single writer (Next.js).
  • Auto-generated OpenAPI gives a typed contract to the TypeScript side.

Instead of all-TypeScript AI (worse toolchain) or all-Python app (rebuild the auth/PWA/app-shell we already had).

NVIDIA NIM — Nemotron, embedding & reranking

Model · inference

NVIDIA Inference Microservices: a small Nemotron for reasoning/extraction, nv-embedqa-e5-v5 for embeddings, and a reranking NIM — behind an OpenAI-compatible API.

  • Data sovereignty. NIMs are self-hostable containers — they run on the trust's own GPUs, so data never leaves. No hosted frontier API can promise that.
  • No lock-in at the app layer. OpenAI-compatible, so models swap without a rewrite and the same code targets hosted or on-prem.
  • A free hosted tier for the demo → identical containers on-prem for production: build for £0, deploy where the data must live.
  • TensorRT-optimised, versioned, and a whole family (LLM + embed + rerank + guardrails) under one vendor.

Instead of a hosted frontier API (can't satisfy on-prem residency) or raw self-hosting with vLLM (you rebuild serving, optimisation, retrieval, and guardrails yourself). NIM is the middle path: self-hostable and batteries-included.

pgvector

Retrieval

A Postgres extension adding a vector column type + ANN indexes — the store for the discharge-policy knowledge base.

  • Reuses the database already in the stack — no separate vector DB to run, back up, or keep consistent.
  • Vectors sit transactionally alongside the relational data, with an hnsw cosine index for approximate-nearest-neighbour search.
  • Right-sized: a policy KB doesn't need a dedicated vector platform. (Graduate to Milvus only if scale demands it.)

Instead of Pinecone/Milvus: extra infra and a second source of truth for a corpus this size.

Deterministic ML (logistic + baseline)

Forecast

Transparent, monotone functions for discharge probability and demand — not an LLM.

  • Forecasting a number wants a calibrated, testable model — not a language model that can't be evaluated and drifts.
  • The LLM's job is to narrate those numbers, never to compute them. This split is the clearest statement of "GenAI where it belongs".

Instead of asking an LLM to predict length-of-stay: the classic anti-pattern — unaccountable and unfalsifiable.

Delivery & assurance

Docker Compose

Delivery

The polyglot stack — Postgres (pgvector image), the FastAPI ai service, object storage — as one reproducible set of containers.

  • One command brings up the whole system; the AI service ships as its own pinned Python image, so the host toolchain is irrelevant.
  • The internal network keeps the AI service off any public surface; only the app is exposed.

Evaluation harnesses

LLMOps

Scriptable gates: extraction F1, RAG hit-rate + faithfulness, ward-state query-intent accuracy, action appropriateness, forecast ranking + narration numeric-consistency.

  • Quality is a number, not a vibe — every AI capability has a labelled set and a pass threshold.
  • They caught a bad first model choice and a hung model in development, and turned prompt tuning into a measured 69% → 88% improvement.
  • They're designed to run as CI gates so a model or prompt swap can't silently regress.

Instead of eyeballing outputs: the difference between "seems fine" and "provably ≥ 0.9".

Auth.js v5 + RBAC

Security

Credentials auth (Argon2id, JWT) with role-based access, inherited from the platform.

  • Auth is enforced once, at the Next.js edge + server; the AI service simply trusts an internal service token.
  • Approvals are attributable — the audit trail ties every action decision to a user.
