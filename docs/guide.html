The complete guide

WardBeat

A hospital ward-flow copilot — it reads the ward's notes and shows who's fit to leave and what's blocking them, so a ward runs at full, safe bed utilisation. This is the single guide to the product, how it works, and why it's built the way it is.

● live on NVIDIA NIM Next.js 16 · FastAPI · Postgres/pgvector Portfolio · generative-AI solution architecture
01

Overview

Wards lose bed capacity not because patients can't leave, but because patient flow stalls and the reason is hard to see — the status that matters (who's medically fit, what's blocking them) lives in free-text notes, and coordination is manual. WardBeat turns that into a live, cited, actionable board.

The thesis — GenAI where it belongs. Generative AI does the language, reasoning, and glue: reading unstructured notes into structured data, grounded question-answering, and turning numbers into prose. Deterministic ML does the forecasting. The system is designed to show when not to use an LLM as much as when to.

The four surfaces (now one cockpit)

Ward board

Every bed at a glance — barriers, discharge probability, and an ⚡ action badge. Click a bed for the full detail drawer.

Copilot (docked)

Ask about live ward state or discharge policy; ward-state answers highlight the beds they reference.

Actions

Policy-grounded next-best actions per bed, approved/dismissed by a human, audited.

Flow briefing

Net bed position + an AI-narrated shift summary, from a deterministic forecast.

Read this first. WardBeat is a decision-support tool: it recommends and drafts; clinicians decide. No model takes an autonomous clinical action, every AI output is grounded and cited, and it runs entirely on synthetic data (zero PHI). That constraint shapes the whole architecture.
02

In the hospital

What WardBeat is for and how it fits a working day on a ward.

The problem

Invisible barriers

A patient is fit for discharge but stuck on TTOs, transport, social care, or a review — with no single current view of why.

Signal buried in notes

Discharge status, EDD, and barriers live in free-text nursing/ward-round notes, not structured fields.

Reactive, not planned

Teams firefight in the afternoon; discharge-before-noon slips and delayed transfers of care build up.

High-friction coordination

Board rounds and handovers are assembled by hand from scattered systems, eating clinical time.

Who uses it

Bed / flow manager

"Free the right beds by noon, safely." Lives on the board + action queue.

Charge nurse

"Know each barrier without re-reading every note." Uses per-bed cards + citations.

Discharge coordinator

"Chase TTOs, transport, social care before they block a bed." Works the actions.

Site / ops manager

"See house-wide flow risk for the next 12–24h." Reads the flow briefing.

Governance lead

"Trust that it's grounded, audited, and safe." Relies on citations + the audit trail.

A morning on the ward

Board

The whole ward at a glance; fit-but-delayed beds stand out.

Run extraction

Read the overnight notes

One click extracts barriers/EDD; each links to the exact source sentence.

Generate policy-grounded recommendations; the coordinator approves the ones to chase — audited, recommend-only.

Copilot

"Who's fit but waiting on transport?" highlights those beds; policy questions get grounded, cited answers.

Briefing

Brief the flow huddle

Net bed position + likely discharges + beds to chase — numbers from a model, words from the AI.

Outcomes it targets · safety · non-goals

Outcomes

Faster spotting of MFFD-but-delayed patients, higher discharge-before-noon, near-zero board-round prep, better bed utilisation vs the safe ceiling.

Safety & governance

Decision-support (non-diagnostic), human-in-the-loop, grounded + cited, fully audited, and on synthetic data with a self-hostable model path so real data can stay in the trust.

Not an EHR

A thin layer on top of systems of record, not a replacement.

Not autonomous

No diagnosis, no triage, no action without a human — and, in this version, not connected to real data or pharmacy/transport systems.

Four planes, with generative AI concentrated in structuring, retrieval, and reasoning; deterministic code does the forecasting and the data.

The request flow behind each capability

1 · Barrier extraction (structuring)

note→small Nemotron → strict JSON→ground quotes to spans→persist

A small model returns schema-constrained JSON (fit-flag, EDD, barriers with verbatim quotes). FastAPI grounds each barrier to its sentence and drops anything it can't locate. The note is data to read, never instructions to follow.

2 · Copilot (retrieval — right tool per data shape)

router→ward-state: validated filter over the board|policy: embed → pgvector ANN→rerank→grounded answer

Ward data is structured, so ward-state questions become a validated allow-listed filter (never SQL). Policy is unstructured, so it's genuine vector RAG. Weakly-supported answers are refused, not hallucinated.

3 · Action recommender (agent, human-in-the-loop)

retrieve policy (tool)→reason → next-best action + rationale→human Approve / Dismiss → audit

A retrieve-then-reason agent recommends one allow-listed action per barrier, justified by policy. Strictly recommend-only: approving marks the barrier in progress and writes an audit row; nothing acts externally.

4 · Forecast & narrate

deterministic discharge + demand models→narrate the numbers→flow briefing

Deterministic functions (no LLM) produce every number; the LLM only narrates them and is forbidden from inventing figures. Asking an LLM to predict a length-of-stay would be the anti-pattern.

The rules that hold everywhere

Grounding over trust

Every output cites its source; unverifiable output is dropped or refused.

Measured, not assumed

Four eval harnesses gate quality (see §5).

Mock ↔ live by one flag

Same contracts run an offline mock or real NIM; the mock is the fallback, so the app never breaks.

Harness, not prompt

Structured I/O, retrieval, tools, a rate-limit token bucket, and eval gates — the prompt is the smallest part.

04

Stack & why

Every technology, and — the part that matters — why it beat the obvious alternative. Two decisions drive the rest:

Polyglot by design — TypeScript runs the product, Python runs the AI, because the GenAI/ML ecosystem lives in Python. One internal service, one front door.  ·  On-prem-capable by default — the AI stack is self-hostable, so clinical data can stay in the trust; that rules out hosted frontier APIs.

Next.js 16

Experience · BFF

App Router + RSC + Server Actions — UI, auth, and the API-for-the-frontend in one framework.

  • Server Actions keep one front door; the AI service + DB stay unexposed.
  • RSC keeps the board fast; auth/RBAC/PWA came with the platform, so the build was about the AI.

Instead of a separate SPA + API: more surface, duplicated auth, nothing gained.

FastAPI (Python 3.12)

AI plane

A small, stateless internal service: extraction, RAG, agent, forecast, narration.

  • Python is where retrieval, agents, evals, and scikit-style models live.
  • Stateless → testable; DB keeps a single writer; OpenAPI gives a typed contract.

Instead of all-TS AI (worse toolchain) or all-Python app (rebuild the auth/PWA/shell).

NVIDIA NIM — Nemotron · embed · rerank

Model

Self-hostable inference microservices behind an OpenAI-compatible API.

  • Data sovereignty — runs on the trust's own GPUs; data never leaves.
  • No lock-in (OpenAI-compatible); free hosted tier for the demo → identical containers on-prem for production.
  • TensorRT-optimised; a whole family (LLM + embed + rerank + guardrails) under one vendor.

Instead of a hosted frontier API (no on-prem residency) or raw vLLM self-hosting (rebuild serving, optimisation, retrieval, guardrails). NIM is the middle path.

pgvector + PostgreSQL 17 + Drizzle

Data

One database for relational data and the policy-KB vectors; type-safe schema and migrations in TypeScript.

  • Reuses the DB already in the stack — no separate vector platform to run.
  • Vectors sit transactionally beside the data with an hnsw cosine index.
  • Drizzle is the single migration authority — keeps the polyglot setup honest.

Instead of Pinecone/Milvus: extra infra + a second source of truth for a corpus this size.

Deterministic ML (logistic + baseline)

Forecast

Transparent, monotone functions for discharge probability and demand — not an LLM.

  • Numbers want a calibrated, testable model; the LLM only narrates them.

Instead of LLM-predicted numbers: unaccountable and unfalsifiable.

Docker Compose · Eval harnesses · Auth.js v5

Delivery & assurance

Reproducible polyglot stack; scriptable quality gates; credentials auth + RBAC.

  • One command runs the whole system; the AI service ships as its own pinned image.
  • Eval gates make quality a number — they caught a bad model choice and drove a measured 69% → 88% improvement.
  • Auth enforced once; every approval attributable in the audit trail.
